# R183 — کنترل اجباری پیش از انتشار، بدون مجوز نصب

این شاخه برای جلوگیری از تکرار تحویل بسته‌های R180/R181 فاقد شرایط نصب است. هیچ بسته جدیدی در این شاخه قابل نصب نشده و `main` و سرویس Windows تغییر نکرده‌اند.

## کارهایی که کنترل می‌کند

- تشخیص ZIP مستقل دارای `release-set.json` در ریشه از ZIP مجموعه/سورس؛ رد بسته‌های UAT، صریحاً فاقد production_pass و بدون qualification Windows/MariaDB.
- تطبیق هویت دقیق نصب‌شده با `supported_baselines`، بررسی SHA256/اندازه فایل‌های artifact، ایمنی ساختار ZIP، و شروط backup/preflight.
- اجرای آزمون‌های ایستا روی Ubuntu/Windows در GitHub Actions، و بررسی مرجع R177 با هش ثابت.
- پیش‌بررسی مرورگر Local: آرشیو چندبسته‌ای و UAT پیش از انتقال بایت‌ها رد شوند. مرورگر تنها یک هشدار اولیه است؛ اعتبار واقعی را Maintenance تعیین می‌کند.

## مرز صداقت فنی

`PASS_STATIC_ONLY` **هیچ‌وقت** یعنی `Installable` نیست. بررسی امضای ECDSA، امتحان native Stage→Activate→Readback، تراکنش مالی، پشتیبان قابل بازیابی و بازیابی کد/DB همچنان جدا لازم‌اند. اگر آزمون‌های موجود این مدارک را ندهند، انتشار Production خودکار مجاز نیست.

این کنترل فقط در CI مختص R183 و در مسیر reusable `workflow_call` تعریف شده است؛ هنوز در تک‌تک workflowهای تاریخی انتشار اجباری نشده و Branch Protection روی مخزن تغییر نکرده است. برای نسخه بعدی، workflow سازنده همان بسته باید `candidate-admission` را به‌عنوان dependency غیرقابل حذف فراخوانی کند و بعد آزمون کامل Stage/Activate، ریکاوری و Business UAT را اجرا کند. هیچ برچسب/مانفیست را برای دورزدن Maintenance دست‌کاری نکنید.
