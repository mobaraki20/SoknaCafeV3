# R259 — تأیید دوطرفهٔ انتقال Public؛ ادامهٔ مستقیم پروژه

**تاریخ:** ۱۶ نوامبر ۲۰۲۶  
**شاخهٔ توسعه:** `qa/sokna-r259-owner-approval-flow-20261116`  
**نتیجه:** **QA PASS** برای جریان تأیید مالکیت و مرورگرِ پابلیک واقعی؛ **انتقال اطلاعات / انتشار = NO-GO**.

## محصول، نه پروژهٔ مخصوص یک کافه
هدف قطعی، جابه‌جایی آسان Local و Public برای هر نصب و هر کافه، مستقل از دامنه، مسیر ریشه یا زیرپوشه، نسخه و هاست است. مسیر کاربر باید کوتاه بماند: در «اتصال‌ها ← وب عمومی»، آدرس مقصد را وارد کند، دکمهٔ «بررسی و انتقال» را بزند، مالک Public مقصد و سپس مدیر Local تأیید کنند؛ باقی کارها خودکار و امن انجام شوند. کاربر نباید SQL، ZIP دستی، Emergency، انتخاب rebind/reenroll و تنظیمات فنی انجام دهد.

**دستور کاربری جدید:** کاربر بر سرعت رسیدن به محصول نهایی، حداقل پیچیدگی و **آزمون عملیاتی مهم به‌جای تکرار آزمون‌های کم‌ارزش** تأکید دارد. از توسعهٔ طولانی با تست‌های زائد خودداری شود؛ کار واقعی اول، چند گیت E2E حیاتی در پایان.

## آنچه در سورس واقعی R259 اجرا شد
- روی خود صفحهٔ اتصال Local همان فرم یک آدرس و یک دکمه مانده؛ JS مسیر «همان Public با آدرس تازه» را از «تأیید مالک مستقل مقصد» جدا می‌کند، بدون اینکه اپراتور حالت فنی انتخاب کند.
- API Local با session واقعی مدیر، CSRF و هویت نصب Local از پیکربندی واقعی، درخواست مهلت‌دار در Ledger ثبت می‌کند. هیچ claim سمت مرورگر به‌عنوان تأیید پذیرفته نمی‌شود. کلیدهای MAC/CSRF مجزا و بیرون از webroot محافظت شده‌اند.
- صفحهٔ مقصد `/move/approve` در همان Public، ورود مدیر، ساخت رمز مالک روی Public موجود با مدیر Staff واقعی و تأیید امضاشدهٔ مالک را انجام می‌دهد؛ اسکریپت و CSS با base path همین نصب سرو می‌شوند؛ کلید و رمز از Public خارج نمی‌شوند.
- پاسخ امضاشده به Local برمی‌گردد؛ مدیر Local مستقلاً تأیید می‌کند؛ PHP سرور از Ledger خودش challenge اصلی را می‌خواند، دو امضای مقصد را بررسی می‌کند و MAC ویژهٔ Local را ثبت می‌کند؛ فقط وضعیت `owner_approved` می‌شود.
- `0075_public_move_owner_approval.sql` Local forward-only است. در Public، **بستهٔ R249/35IC با ۸ migration قبلی به‌صورت بایتی حفظ شده** و 0009/0010 پیشین دست نخورده‌اند. overlay آزمایشی R259 شامل ۲۴۲ فایل است و ZIP قابل نصب ساخته نشده.
- عملیات مهلت‌دار امکان تلاش مجدد و لغو دارد؛ درخواست منقضی می‌تواند بدون پاک‌کردن اطلاعات با درخواست بعدی جایگزین شود.

## آزمون کوتاه و واقعی
فقط دو گیت تعیین‌کننده اجرا شد:
1. دو دیتابیس MariaDB مجزا، درخواست Local تا رسید Ed25519 Public و تأیید مستقل Local، بازخوانی Ledger، رد نشست غیرمجاز، لغو بدون انتقال: **۱۱ PASS**.
2. منبع واقعی pinned R249/35IC، نصب واقعی آزمایشی Public، HTTP login/consent قبلی و GET از Kernel واقعی `/move/approve` و دریافت دو asset زیر مسیر نصب: **۵ PASS برای سطح مرورگر**.

## کار اصلی باقی‌مانده — نه گسترش تست‌ها
**R260 باید مستقیم موتور اجرا را پیاده‌سازی کند:** پیش‌بررسی بدون تغییر → ثبت عملیات قابل‌ازسرگیری → snapshot و backfill داده و تصاویر → reconciliation سفارش باز/در انتظار، کارکنان و داده‌های مالی → readback واقعی → fencing تنها authority و commit کنترل‌شده → rollback/recovery. اتصال Public فعلی تا زمان commit صحیح حفظ می‌شود. سپس مسیر انتقال/بازیابی Local و Windows Print Agent/Runtime انجام شود.

بعد از تکمیل این بخش‌ها، فقط آزمون‌های ضروری نصب واقعی روی دو میزبان مجزا، ریشه/زیرپوشه، ارتقای نسخه‌های موجود، قطع ارتباط و حفظ سفارش/چاپ/داده اجرا شوند؛ سپس بستهٔ یونیورسال تجمیعی آماده شود. **R259 و رسید مالک هرگز مجوز cutover یا انتشار نیستند.**
