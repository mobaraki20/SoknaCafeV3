# SOKNA Prerequisites Setup

این ابزار **Local Web را نصب نمی‌کند**. فقط زیرساخت لازم برای اجرای Local Web را آماده می‌کند.

## سه حالت

- **نصب جدید**: PHP + Apache + MariaDB را از نسخه‌های release-locked دریافت، SHA-256 را بررسی و زیرساخت را آماده می‌کند.
- **تعمیر**: فایل‌ها/تنظیمات مدیریت‌شده و سرویس‌ها را ترمیم می‌کند و `Web` و `Data` را نگه می‌دارد.
- **بازیابی بعد از نصب مجدد ویندوز**: از زیرساخت و Data باقی‌مانده روی درایو دیگر استفاده و سرویس‌های Windows را دوباره ثبت می‌کند. Data موجود initialize نمی‌شود.

## مسیر پیشنهادی

مثلاً:

```text
D:\SOKNA\Infrastructure\PHP
D:\SOKNA\Infrastructure\Apache
D:\SOKNA\Infrastructure\MariaDB
D:\SOKNA\Data\MariaDB
D:\SOKNA\Web
D:\SOKNA\Backups
```

درایو و ریشه قابل انتخاب است. استفاده از درایوی غیر از درایو Windows پشتیبانی می‌شود.

## مرز دیتابیس

Prerequisites Setup فقط MariaDB Server و Data Directory زیرساخت را آماده می‌کند.  
**Database مربوط به SOKNA، user محدود برنامه و migrationها در Browser Setup خود Local Web ساخته می‌شوند.**

بعد از آماده‌شدن زیرساخت، بسته Local Web جداگانه مستقیماً داخل `Web` Extract می‌شود. Apache پوشه `Web\public` را سرو می‌کند و آدرس نهایی Local Web را Setup نمایش می‌دهد؛ نمونه پیش‌فرض `http://127.0.0.1:18080/` است.

## خطا و پشتیبانی

Logها در `<root>\Infrastructure\Logs` نگه‌داری می‌شوند. نصب MariaDB یک MSI verbose log جدا دارد. دکمه «ساخت بسته پشتیبانی» state، diagnostics و logهای اخیر را ZIP می‌کند و عمداً password/credentialهای Local Web را وارد بسته نمی‌کند.

اگر Data قبلی MariaDB تشخیص داده شود، حالت نصب جدید متوقف می‌شود و کاربر باید Repair یا Recover را انتخاب کند.

## نصب موجود روی Root دیگر

قبل از هر تغییر روی PHP/Apache/MariaDB، Setup مالکیت سرویس‌های `SoknaApache` و `SoknaMariaDB` و registration نسخه قفل‌شده MariaDB در Windows Installer را بررسی می‌کند.

اگر مثلاً نصب قبلی روی `D:\SOKNA` باشد و کاربر `E:\SOKNA` را انتخاب کند، عملیات **قبل از ساخت/تغییر Root جدید متوقف می‌شود**. Setup مسیر سرویس/Data قبلی را گزارش می‌کند و هیچ Migration، حذف، Uninstall یا جابه‌جایی خودکاری انجام نمی‌دهد.

- برای ادامه استفاده از نصب قبلی، همان Root قبلی انتخاب و Repair/Recover اجرا می‌شود.
- برای نصب واقعاً تازه روی Root جدید، نصب قبلی باید پس از Backup و تصمیم صریح اپراتور تعیین تکلیف شود.
- نصب موازی همان نسخه MariaDB در Root جدید در حالی که Windows Installer آن را در Root دیگری ثبت کرده، مجاز نیست؛ این حالت به‌جای ورود خاموش MSI به Maintenance Mode با پیام روشن متوقف می‌شود.


## نسخه و وضعیت دانلود

نسخه خود Setup همیشه در عنوان پنجره نمایش داده می‌شود و همان نسخه در Log ثبت می‌شود.

برای هرکدام از PHP، Apache و MariaDB یک بخش مستقل وجود دارد که نسخه، نام فایل، حجم، وضعیت و Progress همان فایل را نشان می‌دهد. علاوه بر آن یک Progress کلی برای کل فرایند وجود دارد.

هنگام دانلود، مقدار واقعی دریافت‌شده، حجم کل قفل‌شده، سرعت واقعی انتقال و ETA نمایش داده می‌شود. اگر سرور Content-Length اعلام کند، مقدار آن با اندازه release-lock تطبیق داده می‌شود. پاسخ اولیه سرور timeout کوتاه دارد و توقف دریافت داده نیز جداگانه تشخیص داده می‌شود.

## نصب آفلاین

این Setup به اینترنت وابسته نیست. برای هر dependency می‌توان «انتخاب فایل» را زد و فایل رسمی را از دیسک/فلش تحویل داد. همچنین «انتخاب پوشه آفلاین» سه فایل PHP/Apache/MariaDB را در یک Offline Kit پیدا می‌کند.

فایل دستی فقط پس از تطبیق Size و SHA-256 وارد Cache تأییدشده می‌شود. بعد از آن همان فرایند نصب خودکار ادامه پیدا می‌کند.

اگر دانلود آنلاین از همه منابع شکست بخورد، Setup به‌جای انتظار طولانی امکان انتخاب همان فایل از کامپیوتر را پیشنهاد می‌کند. دانلود ناقص نیز برای Resume بعدی نگه داشته می‌شود.

برای Windows Services، فایل VC++ Runtime نیز می‌تواند در Setup سرویس‌ها با «انتخاب فایل از کامپیوتر» تحویل داده شود و علاوه بر Size/SHA-256، امضای Microsoft هم بررسی می‌شود.


## تداخل پورت Apache

پورت پیش‌فرض Local Web برابر 18080 است و به پورت 80 وابسته نیست. قبل از ثبت/شروع Apache، Setup امکان bind روی پورت انتخاب‌شده را بررسی می‌کند. اگر پورت اشغال/رزرو شده باشد، نام فرایند/PID را در صورت امکان گزارش می‌کند و یک پورت آزاد از میان 18081، 18082، 18083، 8080، 8081، 8088، 8000 و 8888 پیشنهاد می‌دهد.

پورت انتخاب‌شده در تنظیم Apache و `infrastructure-state.json` ثبت می‌شود و آدرس نهایی Local Web بر همان مبنا نمایش داده می‌شود. هشدار `ServerName` نیز با تنظیم `ServerName 127.0.0.1:<port>` حذف می‌شود. Endpoint فقط loopback است و همان scheme/host/port بعداً توسط Browser Setup در Runtime و Print Agent Pairing ثبت می‌شود.
