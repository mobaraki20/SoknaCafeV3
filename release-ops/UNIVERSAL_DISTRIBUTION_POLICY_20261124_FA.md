# سیاست انتشار یونیورسال سکنا — ۲۴ نوامبر ۲۰۲۶

این تصمیم جایگزین الزام دریافت شواهد یک میزبان واقعی برای **صدور بسته عمومی** در مستندات قدیمی کارخانه است. مسیرهای تاریخی QA و رسیدهای آنها تغییر نمی‌کنند.

- یک مجموعه نسخه از سورس تاییدشده؛ Local Update، Public Update، Local Clean Web، Public Clean Web. نسخه و SHA هر فایل منجمد می‌شود. فایل آزمایشگاهی به‌صرف تغییر نام یا پرچم قابل انتشار نیست.
- یونیورسال یعنی یک بسته برای همه مبدأهای اعلام‌شده و آزموده‌شده، بدون انتخاب دستی نسخه توسط کاربر؛ نه پذیرش نسخه یا هش ناشناخته. برای هر مبدأ اعلام‌شده، گیت ارتقا لازم است. اگر مسیر مستقیم نامعتبر است، مسیر مهاجرت رسمی باید در محصول/سازنده از قبل وجود داشته باشد؛ بدون جعل wildcard.
- قبل از انتشار: شواهد آزمایشگاهی روی همان بایت‌ها، ساختار و هش، دیتابیس، نصب تمیز، Native Windows، Routine/Emergency، حفاظت فایل‌های ثابت، بازیابی و خطاهای مرتبط؛ هیچ شواهد مخصوص کافه/خانه لازم نیست. تأیید صاحب محصول برای محدوده سورس و بسته مستقل از پذیرش میدانی است.
- در زمان نصب: خود موتور هویت نصب‌شده، قابلیت موتور، SHA و سازگاری مبدأ، بکاپ و Snapshot، مرز دیتابیس، توقف یا صف سفارش‌ها، فعال‌سازی، خواندن سلامت و بازیابی را کنترل کند. اگر شرایط برقرار نیست قبل از تغییر متوقف شود؛ بررسی پذیرش پس از نصب جداگانه است.
- ارسال بسته پشتیبانی یا فایل بازیابی به کارخانه شرط انتشار/نصب عادی نیست؛ فقط عیب‌یابی در صورت نیاز. بکاپ باید در محل امن میزبان ایجاد و بررسی شود و نباید به GitHub ارسال شود.
- ماشین‌آلات Windows Services/PrintAgent/Maintenance/Emergency مستقل باقی می‌مانند. Clean Web جایگزین نصب‌کننده سرویس ویندوز نیست.
- مسیر جدید universal-release در کارخانه مشترک، قرارداد نسخه‌بندی‌شده و شواهد Run/Job پین‌شده را می‌خواند و فقط فایل‌های اپراتوری منجمد با SHA تأییدشده را منتشر می‌کند. نه deploy، نه تغییر میزبان، نه بازنویسی پرچم QA. نتیجه BLOCKED_PACKAGE_QUALIFICATION با دلایل مربوط به خود بسته است، نه نبودن بسته پشتیبانی مشتری.
