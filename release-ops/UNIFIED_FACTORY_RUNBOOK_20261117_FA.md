# مسیر یکپارچه QA انتشار سکنا در GitHub — ۱۷ نوامبر ۲۰۲۶

**وضعیت:** ابزارهای قبلی اکنون از یک Workflow مشترک فراخوانی می‌شوند؛ **تأیید نصب عملیاتی و انتشار خودکار هنوز فعال نیست**.

## اجرای ساده

در مخزن GitHub به [Actions: SOKNA Unified Release Factory - QA ONLY / NO DEPLOY](https://github.com/mobaraki20/SoknaCafeV3/actions/workflows/sokna-release-factory.yml) برو؛ **Run workflow** را بزن و `checkpoint = R233-20261115` را انتخاب کن.

این شناسه تنها مرجع دارای سورس کاملِ دقیق و بسته‌ساز QA بایت‌سنجی‌شده در این Workflow است. **با نسخه R233 بستهٔ جدیدتر کافه منتشر نکن.** قبل از هر درخواست انتشار تازه باید آخرین Workspace و تصمیم‌های ACCEPT/HOLD بازخوانی و سورس واقعاً تأییدشده با SHA جدید ثبت شود. اگر سورس تغییر کند، این Workflow اجازه ندارد موفقیت آزمون قدیمی R233 را به نسخه جدید نسبت دهد؛ تا اتصال سازنده و آزمون همان نسخه، fail-closed باقی می‌ماند.

## ترتیب واقعی داخل یک اجرا

۱. **Local Source Intake:** دریافت SOURCE-ONLY از آرشیو منجمد GitHub؛ SHA و Source Tree، ۸۱ Migration، تطبیق ماژول‌ها با ماتریس ۷۲کنترلی، هویت قالب Local Maintenance.

۲. **Public Source Intake:** همان کنترل‌ها برای Public با ۸ Migration و قالب Update.

۳. **ساخت بسته‌های موقت QA:** استفاده مجدد از `qa_local_maintenance_rehearsal.py` (Local Release Set 2.1) و `qa_public_update_rehearsal.py` (Public Routine/Emergency با همان SHA و Clean Root هم‌نسخه). **آن‌ها بسته نصب عملیاتی نمی‌سازند**؛ خروجی‌های ZIP در فضای موقت Runner هستند و در Artifact عمومی/قابل دانلود منتشر نمی‌شوند.

۴. **آزمون‌های موجود:** Windows Server 2022/PowerShell 5.1، تطبیق ساختار و SHA، چهار مسیر PHP Public از مبدأهای 35HK/35HT، MariaDB 11.4 با اجرای مجدد Migration و دو بازیابی مستقل، کنترل ثبات داده‌ها و عدم تغییر غیرضروری سرویس‌ها در محدوده‌ای که آزمون انجام می‌دهد.

۵. **تصمیم مستقل:** `factory_decision.py` گزارش‌های همان اجرای واحد را از GitHub دریافت می‌کند؛ هر پنج شاهد Local/Public/DB و Source Intake باید PASS و SHAها منطبق باشند. فقط گزارش `SOKNA-UNIFIED-RELEASE-READINESS-REPORT-ONLY` منتشر می‌شود.

## مفهوم وضعیت نهایی

- `QA_PASS_EXTERNAL_HOST_ACCEPTANCE_BLOCKED`: آزمون‌های GitHub که مشخص شده‌اند موفق بوده‌اند؛ هنوز **هیچ مجوز نصب یا بسته قابل نصب عملیاتی** نیست.
- `BLOCKED_MISSING_OR_FAILED_QA`: مدرک ناقص، خطا یا SHA/نسخه/خط مبنا نامعتبر؛ تولید و انتشار عملیاتی قطعاً ممنوع است.

پرچم `production_authorized` همواره `false` است؛ هیچ گزینه «انتشار با وجود هشدار» یا تغییر پرچم برای دورزدن کنترل اضافه نشده است.

## مدرک لازم برای انتقال به نسخه قابل نصب

برای همان ZIP نهایی و همان SHA، باید این موارد به صورت مستقل بررسی شوند:

| موضوع | حداقل شاهد قبول |
|---|---|
| سورس/تاریخچه اصلاحات | آخرین Workspace تأییدشده، ماتریس REG-003، بدون ورود ۲۷ تصمیم HOLD |
| مبدأهای واقعی | هویت Full/Delta و قابلیت نصب Local/Public در نسخه‌های اعلام‌شده؛ نام دستگاه یا VERSION به‌تنهایی کافی نیست |
| Windows Local | Preflight، Stage، Activate، Readback، Backup و Recovery با Maintenance روی Windows میزبان آزمون |
| دیتابیس | تغییر از نمونه دیتابیس قدیمی واقعی، حفظ تراکنش/تسویه/انبار و DB-forward-fence با تست قطع عملیات |
| Public Host | HTTP/HTTPS واقعی، Root/Subpath، همان SHA در Routine/Emergency، QR قدیمی، کلیدهای محفوظ و نصب خالی |
| سرویس‌های ویندوزی | KEEP دقیق Runtime/PrintAgent/Maintenance، SCM/UAC/ACL، reboot/repair/fault cycles |
| چاپ | سفارش→صف→Agent→اسپولر→فیش کاغذی بدون حذف یا چاپ تکراری؛ تست ۵۸/۸۰ میلی‌متری |
| عملیات مالی و ارتباطی | سناریوهای تسویه جزئی، استرداد، موجودی و همگام‌سازی در حین/پس از آپدیت |
| ثبت پذیرش | میزبان Home/Cafe جداگانه، زمان، نسخه‌های فعال، SHA همان فایل، Transaction ID، PASS/FAIL/NOT_RUN و تأیید صاحب محصول |

**هیچ‌یک از اینها نباید صرفاً با سبزبودن GitHub یا داشتن فایل JSON ساختگی «موفق» تلقی شود.** برای انتشار واقعی، سازنده نسخه تأییدشده باید به همین مسیر متصل شود و آزمون نصب و بازگشت بر همان فایل نهایی اثبات شود؛ از این مرحله نمی‌توان با یک دکمه نسخه عملیاتی سالم را تضمین کرد.

## اصول غیرقابل نقض

- GitHub مسیر اصلی هماهنگی سورس، کنترل بسته، شواهد و تصمیم انتشار است، نه موتور جدید نصب و نه مخزن اسرار کافه.
- هر کافه، میزبان، دامنه و Subpath متغیر است؛ هیچ آدرس خاصی در سازنده به‌صورت ثابت قرار نمی‌گیرد.
- هیچ سورس برنامه، Windows Runtime، Maintenance، PrintAgent، میزبان عملیاتی یا دیتابیس از این Workflow تغییر نمی‌کند.
- نتیجه آزمون R233 به R262/R263 یا نسخه جدیدتر قابل تعمیم نیست.
- مشاهده نسخه `for_install=true` در Manifest آزمایشی به معنی اجازه انتشار نیست.
- قرارداد Windows و [ممیزی ۷۲کنترلی](INDEPENDENT_SYSTEM_COVERAGE_AUDIT_20261116_FA.md) پیش از انتشار هر نسخه بازبینی می‌شوند.
